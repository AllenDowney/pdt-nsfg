# Working in pdt-nsfg

NSFG metadata built to the PublicDataToolkit standard (`../PublicDataToolkit/STANDARD.md`).

- `metadata/` (except `corrections.jsonl`) and `build/report.md` are generated by `build/build_slice.py`; edit the build or `build/slice.yaml`. `metadata/corrections.jsonl` is edited by hand.
- `data/` is gitignored and never committed. In `data/raw/`, the 2022-2023 files link to `~/MarriageNSFG`; the 2017-2019 data and dictionaries are copies from ftp.cdc.gov; the questionnaires and 2017-2019 codebooks are in `data/raw/cdc/` (cdc.gov returns 403 to scripts; see `sources.yaml`).
- Two releases, 2022-2023 and 2017-2019, each with three tables (female, male, pregnancy), declared in `dataset.yaml`. Names like `MARSTAT` appear in more than one table, so references must name the table. Each release spells names as its codebook does (2017-2019 writes computed variables in lowercase: `age_r`, `pregordr`).
- The NSFG codebook doesn't mark missing codes; the build types them by a rule over labels (`nsfg_missing_from_labels`).
- The codebooks are PDFs converted with `pdftotext -layout`. 2022-2023 uses NCHS's layout (`parse_codebook` in `build/build_slice.py`: page-break headers, margin boxes); 2017-2019 uses ICPSR's (`build/icpsr_codebook.py`), and its female section A is OCR text with misread names and column numbers. The build checks every code's count against the data and reports a mismatch.
- 2022-2023 question text comes from the CAPI-lite questionnaires (`build/capilite.py`, rule `nsfg_capilite_text`); 2017-2019's is in its codebooks.
- `metadata/links.jsonl`: links NCHS's summary of questionnaire changes asserts (`publisher_links` in `build/slice.yaml`), and `same_item` links by rule `nsfg_identical_documentation`. Shared names the rule doesn't link are listed in `build/report.md` with what differs. Never link by inference.
